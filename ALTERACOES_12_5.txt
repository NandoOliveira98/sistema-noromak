VERSÃO 12.5 — MERCADO LIVRE: NOME FISCAL, FULL E DATA DE DESPACHO

1. CLIENTE / DADOS FISCAIS
- A API passa a obter buyer.billing_info.id no pedido.
- Consulta /orders/billing-info/{site_id}/{billing_info_id}.
- O campo Cliente usa nome + sobrenome fiscal; para CNPJ, usa a razão social retornada em name.
- Fallback: receiver_name do envio, depois nickname/nome do buyer.
- Nome fiscal fica registrado em NomeFiscalMercadoLivre.

2. IGNORAR MERCADO ENVIOS FULL
- Detecta logistic.type/logistic_type = fulfillment/full.
- Pedidos Full não entram em conf_pedidos.
- Orders_v2/Shipments registram IGNORADO / FULL no log.
- Sincronização manual contabiliza ignored_full separadamente.
- Se uma versão anterior já tiver criado linha de API para um pedido Full, a nova sincronização remove somente essa linha originada pela API.

3. DATA LIMITE DE DESPACHO
- Prioriza GET /shipments/{shipment_id}/sla e o campo expected_date.
- Exemplo: expected_date 2026-08-31T23:59:59-03:00 -> Data do Pedido = 2026-08-31.
- estimated_handling_limit antigo fica apenas como fallback.
- Se a API não informar nenhum prazo, usa a data local atual.
- Não usa estimated_delivery_limit como prazo de despacho, pois é prazo de entrega/cancelamento, não de postagem.

4. SKU
- Mantida a normalização da V12.4: 155172-ACP429/9-B -> ACP429/9-B.
