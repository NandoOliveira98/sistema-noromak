SISTEMA DE CONFERÊNCIA NOROMAK — WEB/LINUX 7.2
================================================

O QUE FOI TRANSFORMADO
----------------------
- A versão portátil Windows foi convertida em aplicação Web para Linux.
- O servidor escuta em 127.2.0.1:8100.
- Todas as telas e APIs funcionam sob o prefixo /expedicao.
- Não existe uma segunda tela de login: o sistema usa a sessão do NoromakWeb.
- Para identificar a pessoa, o servidor consulta somente:
  http://127.2.0.1:8000/api/v1/auth/me
- Os perfis Admin/Operador são próprios da Expedição e ficam no SQLite.
- O banco permanente fica em /home/expedicao/dados/expedicao.db.
- O banco não é apagado nas publicações.
- Pedidos concluídos são removidos imediatamente dos pendentes no Admin e na Conferência.
- O QZ Tray continua imprimindo na impressora instalada no computador do operador.

ARQUIVOS PRINCIPAIS
-------------------
servidor_web.py              Servidor Web/Linux sem dependências externas.
expedicao                    Inicializador usado pelo systemd.
APP/admin.html               Painel administrativo.
APP/conferencia.html         Tela dos conferentes.
APP/shared-storage.js        Comunicação com o SQLite pela API.
APP/web-auth.js              Login integrado e gestão Admin/Operador.
publicar.sh                  Publicação e verificação real da porta 8100.
MIGRACAO_INICIAL/            Dados da versão 6.9 importados somente se o SQLite estiver vazio.

PRIMEIRA INSTALAÇÃO
-------------------
1. Extraia o ZIP em uma pasta nova.

2. No Git Bash aberto nessa pasta, prepare o projeto Git uma única vez:

   ./PREPARAR_GIT_UMA_VEZ.sh

   O script conecta esta pasta ao histórico que já existe no servidor e cria
   automaticamente o commit da versão Web/Linux.

3. Instale a chave de assinatura QZ no servidor uma única vez:

   ./instalar_servidor_uma_vez.sh

   A consulta do serviço não usa sudo e, portanto, não pede senha. Se sua conta
   não puder visualizar o serviço, a chave ainda assim permanecerá instalada.

4. Publique:

   ./publicar.sh

5. Abra:

   https://noromakweb.com.br/expedicao

IMPORTANTE SOBRE O SERVIÇO
--------------------------
O ExecStart correto é:

   /home/expedicao/app/expedicao

Se estiver diferente, o responsável pelo servidor deve aplicar o modelo
expedicao.service.example. A conta de publicação precisa ter permissão sem senha
somente para reiniciar o serviço expedicao, como previsto no manual.

PRIMEIRO ADMINISTRADOR
----------------------
O username da variável EXP_ADMIN_USUARIO em /home/expedicao/.env é cadastrado
automaticamente como Admin da Expedição. O valor informado no manual é luis.

Para liberar outras pessoas:
1. Entre no painel /expedicao/admin.
2. Abra a aba Usuários.
3. Informe exatamente o username que a pessoa usa no NoromakWeb.
4. Escolha Admin ou Operador e salve.

Não são criadas nem armazenadas senhas próprias da Expedição.

QZ TRAY — UMA VEZ EM CADA COMPUTADOR
------------------------------------
Execute CONFIGURAR_QZ_TRAY_WEB.bat como administrador uma única vez em cada PC
que imprime. Depois, mantenha o QZ Tray aberto. A configuração não precisa ser
repetida diariamente.

IMPORTANTE: a versão Web 7.2 usa um novo certificado. Mesmo computadores que já
foram configurados para a versão portátil 6.9 precisam executar o novo arquivo.

MIGRAÇÃO DOS DADOS DA VERSÃO 6.9
--------------------------------
Na primeira inicialização, se o SQLite estiver vazio, o servidor importa produtos,
etiquetas, histórico e demais dados disponíveis em MIGRACAO_INICIAL.

Depois que /home/expedicao/dados/expedicao.db existir, novas publicações não
reimportam nem substituem o banco.

BACKUPS
-------
O servidor cria um backup diário em /home/expedicao/backups e mantém os 15 mais
recentes.

COMO SABER SE O DEPLOY FUNCIONOU
--------------------------------
O publicar.sh testa diretamente:

  http://127.2.0.1:8100/api/health

Essa é a confirmação real do aplicativo. O código 200 do endereço público sozinho
não basta, porque ele pode ser a página de login do NoromakWeb.

DIAGNÓSTICO
-----------
Execute:

  ./verificar_servidor.sh

Ele mostra o status do serviço, os últimos logs e o health interno.

SEGURANÇA
---------
- SEGREDOS_SERVIDOR está no .gitignore e não é enviado no git push.
- A chave privada QZ fica em /home/expedicao/qz com permissão 600.
- Toda API valida a sessão do NoromakWeb e o perfil próprio da Expedição.
- Operadores não podem alterar produtos, etiquetas, usuários nem configurações administrativas.
